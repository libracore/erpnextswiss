§4Tariff import

Duplicate rules

  • name = QST-{canton}-{year}-{ESTV creation date}
  • hash = sha256 of sorted data lines
  • same name · same hash → skip
  • same name · other hash → error, nothing imported
  • new name · hash = latest revision → skip
  • otherwise → new revision · first_imported_on

Canton filter & storage

  • only QST Canton.import_tariffs · none marked → all
  • flag set automatically when an employee record uses the canton
  • model (Monthly/Annual) copied from QST Canton per revision
  • record 12 → commission % · record 13 → median (tariff C)
  • ids: sequence block reserved, then bulk insert (10k chunks)
  • 2026 all cantons ≈ 3.2M rows · ZH 24’972 · GE 32’067

ESTV record 06 · progressive tariff (spec example)

06record 01tx new BEcanton B2N tariff code 20250101valid from 000650100income from 6’501.00 000005000step 50.00 sex 02children 000000000min tax 0.00 00715rate 7.15% status
Bgroup A B C D E G H L M N P Q 2children 0–9 Nchurch Y/N
  • 00 header · creation date = revision marker
  • 11 HEN/MEN/NON… · 12 PEL/PPA/PSP · 13 MED
  • 99 trailer · count incl. 00 + 99
  • G/Q → always x9N · missing Y/N → other variant used
  • tx 02/03 (mutation/deletion) → rejected

§6Retro corrections

Mechanism · ledger, not change detection

  • scope: Jan 1 of slip year · previous year if slip month ≤ cutoff
  • income per month rebuilt from submitted slips + current slip
  • expected tax per month with today’s records & latest tariffs
  • paid = Σ QST Slip Detail.tax of submitted slips
  • current month → qst_component
  • past months: Σ deltas → correction_component, one detail row per month
  • cancelled slip drops out → next slip corrects automatically

Triggers covered

  • employee record added/changed (marriage, child, canton, side job)
  • corrected tariff re-imported
  • salary change / bonus (Jahresmodell)
  • component reclassified (qst_type)
  • no longer liable → refund

Locks · no correction

  • month before go_live_date
  • month with qst_skip slip
  • a later month already submitted (warning-free skip)
  • |delta| < min_correction
  • Jahresmodell + Year-end mode: only December or exit slip

§9Review checklist

TypePointWhereDetails
Assumptionmin tax applied to taxable income, only if taxable > 0calculation.tax_amount
What
tax = max(taxable × rate, minimum tax) · per month · also when earlier months are recalculated
Why
ESTV record format §4.4: “income × rate < minimum tax → minimum tax” · 2026: min tax in every row for AR GL LU NW OW SG SH SO UR AG
Effect
entry on the 31st still pays the full minimum · zero or negative taxable → no tax
Decide
minimum on taxable income as implemented, or pro rata in entry/exit months? check with one affected canton
AssumptionJahresmodell 13th salary counted when paid, or projected from January (setting, off)calculation.annual_rdi
What
default: 13th salary enters the annual rate-determining income when paid · “Project 13th salary when known”: 1/12 of annual periodic pay added from January for months not yet covered by a payout (per 13th frequency)
Why
KS45 §7.1: Swissdec guideline (realisation principle) · KS45 §7.3.1: a known 13th may be included from January
Effect
off: rate slightly low until payout, then corrections for all earlier months · on: rate right from January if the 13th is one month’s pay, payout only corrects a difference · detection: employee’s active salary structure contains an earning tagged 13th Salary (not Additional Salary) · hourly wages and Monatsmodell unaffected
Decide
keep off if Swissdec certification (PAY-001) requires the realisation principle
AssumptionJahresmodell full year = projection · partial year = 360-day averagepayroll.calculate
What
employed all year: past periodic pay + current month × remaining months · joined or leaving this year: Σ periodic × 360 ÷ Σ days
Why

Effect
variable monthly pay not marked as hourly swings the projection → frequent corrections · entering an exit date switches to the average method
Decide
acceptable, or mark variable-pay staff as hourly wage
